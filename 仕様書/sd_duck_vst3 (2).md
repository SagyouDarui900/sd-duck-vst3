# SD-Duck - REAPER向け軽量ビジュアル・ダッキング VST3 仕様書 (v1.0 最終確定版)

## 1. プロジェクト概要・開発背景

### 1.1 基本情報
- **プラグイン名**: `SD-Duck`（リポジトリ名: `sd-duck-vst3`）
- **ベンダー名（Manufacturer）**: `SagyouDarui`
- **プラグイン形式**: VST3（64-bit専用 / インストーラ不要のバンドル配布）
- **対応環境**: Windows 11（x64） / REAPER v7.x 以降
- **技術スタック**: C++20 / JUCE 8 / CMake（GitHub Actionsによる自動ビルド対応）
- **ライセンス**: GNU General Public License v3.0（`GPLv3`）

### 1.2 解決する課題（YTPMV / 音MAD制作ワークフローの最適化）
REAPER標準の `ReaComp` や既存のフリーサイドチェインVSTには以下の課題があり、本プラグインはこれらを単一かつ超軽量なプラグインで解決する。

1. **視覚的フィードバックの不足**: `ReaComp` は時間軸上で「どのタイミングで・どのくらいの深さ・どのようなカーブで音量が下がっているか」を波形で直感的に把握しづらい。
2. **REAPER特有のBPM変化・シーク時のタイミングズレ**: 既存のLFO系ダッキングVSTは、プロジェクト内のBPMマーカーによるテンポ変化や再生位置の途中変更（シーク）時に位相がズレる問題がある。
3. **ロングテールなKick（Gabbaキック等）への対応**: 音MAD/YTPMVで頻出する減衰の長いキックをそのままサイドチェイン入力にすると、ダッキングが解除されず音量が下がりっぱなしになる。
4. **ルーティング設定の煩雑さと確認のしづらさ**: REAPERの `ch 3/4` へのセンド設定やピンコネクタの接続が正しく機能しているか、プラグイン画面上で即座に判別できない。
5. **帯域別・Mid成分ダッキングの簡略化**: キックとベースの低音被り解消や、ボーカルとオケ（Pad等）のセンター成分の干渉回避を、複雑なマルチバンドコンプやダイナミックEQを組まずに実現したい。

### 1.3 設計スコープ・非採用機能（v1.0）
- **ベジェ曲線ドラッグエディタは非搭載**: 描画および操作の軽量性・単純さを優先し、画面上で制御点をドラッグするカーブエディタは設けない。カーブ形状は `Curve` パラメータ（$-1.0 \sim +1.0$）の単一値による連続変形方式を採用する。
- **独自プリセットブラウザUIは非搭載**: ウィンドウの省スペース化のため独自プリセット管理UIは実装せず、APVTSを介してREAPER標準のFXプリセット機能（`.rpl`）およびFX Chain保存に完全対応させる。

## 2. コア機能仕様

### 2.1 トリガーモード（3方式切り替え・すべてMVP v1.0.0に実装）
用途や素材の特性に応じて、以下の3つの動作モードを切り替え可能とする。Audio SidechainとMIDI Triggerは共通のワンショット・エンベロープエンジンを共有する設計とする。

| モード名 | 動作概要 | 主な用途・メリット |
| :--- | :--- | :--- |
| **Tempo Sync (LFO)** | 外部ルーティング不要で、DAWのテンポ（拍・小節）に同期して指定カーブ通りにダッキングを行う。 | 4つ打ちキック等、一定リズムのダッキング。センド設定が不要で最速で適用可能。 |
| **Audio Sidechain** | 外部オーディオ入力（`ch 3/4`）の音量レベルを検出し、エンベロープフォロワーでダッキングを行う。 | 不規則なリズムのキック、ボーカルに合わせたオケのダッキング。 |
| **MIDI Trigger** | トラックに入力されたMIDIノートオン信号をトリガーとして、設定したエンベロープカーブを実行する。 | ゴーストMIDIトラックを用いた精密なタイミング制御。 |

#### モード別の詳細動作仕様
- **Tempo Sync モード（BPM変化・シークズレ完全防止＆停止時収束）**:
  - 内部タイマーによる自走カウントを禁止し、`juce::AudioPlayHead::PositionInfo` から取得した現在の音楽的タイムライン位置（`ppqPosition`）から位相 $p \in [0, 1)$ を毎サンプル直接算出する。
  - プロジェクト途中のBPM変更マーカー、変拍子、ループ再生、再生位置のランダムシーク時においてもタイミングズレをゼロに抑える。
  - **再生停止時の挙動**: ホストが再生停止中（`isPlaying == false`）の場合は、目標ゲイン $g_{\text{target}}$ を `1.0` にセットし、最終段スムージングフィルタを通じて約 `3〜5 ms` 以内に滑らかに `1.0`（バイパス状態）へ収束させる。これにより停止時のプチノイズと予期しない音量減衰を防ぐ。
- **Audio Sidechain モード（ガバキック対策：Detection Type切り替え）**:
  - **Follow (通常)**: 入力音声のエンベロープ（音量変化）に忠実に追従する。ボーカルやスネア等のダッキング向け。
  - **One-Shot (トランジェント)**: 入力信号が `Threshold` を超えた瞬間（立ち上がり）のみをトリガーとして検出し、その後の入力音声の尾引き（サステイン・リリース）を無視して、設定された `Hold` と `Release` の時間通りに元の音量へ復帰する。再トリガーには一定のリトリガー不応期（`30 ms`）およびヒステリシス（$-3\text{ dB}$）を設ける。
- **MIDI Trigger モード（サンプルアキュレート検出）**:
  - `processBlock()` 内の `juce::MidiBuffer` をサンプル単位で走査し、ノートオン（`isNoteOn()`）のサンプル位置（`samplePosition`）で正確にエンベロープをトリガーする。
  - **ノートフィルタ（`midi_note`）**: パラメータ値 `0` の場合はすべてのMIDIノート（`Any Note`）で反応し、`1 〜 128` 指定時は実MIDIノート番号 `0 〜 127`（`parameterValue - 1`）の特定ノートのみに反応する。
  - **ベロシティ感度（`midi_vel_sens`）**: `0%`（デフォルト）ではベロシティに関わらず常に `Depth` 設定値通りの深さでダッキングし、`100%` に近づくほどノートオンのベロシティ値に比例して実効 `Depth` をスケーリングする。

### 2.2 サイドチェインモニタリング（`SC Listen`）仕様
- `sc_listen = On` に設定された場合、メイン音声（`ch 1/2`）の加工および出力を一時的にミュートし、サイドチェイン入力（`ch 3/4` に `SC HPF` / `SC LPF` フィルタを適用した検出用信号）をメイン出力（`ch 1/2`）へスルー出力する。
- これにより、トリガー信号のフィルタリング具合やルーティング接続状態を耳で直接確認できる。

### 2.3 ミックス補助機能（周波数帯域制限・MS処理・Dry/Wetミックス）
- **Split-Band Ducking（低域限定ダッキング）**:
  - 有効/無効トグル（`split_enabled`）とクロスオーバー周波数（`split_freq`: $30.0 \sim 500.0\text{ Hz}$）を独立したパラメータとして持つ。
  - 有効時は4次Linkwitz-Riley（LR4）フィルタ（$24\text{ dB/oct}$）で入力信号を低域（Low）と高域（High）に分割する。LR4フィルタの特性により、Low+High再合成時の振幅応答はフラットに保たれる。ダッキング処理は**低域成分のみ**に適用し、高域成分は原音のまま再合成する。
- **Target Channel（Stereo / Mid-Only）**:
  - ダッキング対象を `Stereo (L+R)` と `Mid (センター成分のみ)` から選択可能にする。
  - `Mid` 選択時は入力を $M = 0.5(L + R)$, $S = 0.5(L - R)$ に変換し、$M$ 成分にのみゲインリダクションを適用して再合成する（ボーカル発声時にオケやPadのセンター帯域だけを自然に引っ込める用途）。
- **Dry/Wet Mix（`mix`）の取得ポイント**:
  - **Dry信号**はプラグイン入力の最初（LR4クロスオーバーフィルタ適用前）の未処理原音から取得し、**Wet信号**はSplit-BandおよびMS処理を通過した後の最終処理済み出力とする。これにより、`Split-Band = On` かつ `Mix < 100%` の設定時でも位相干渉のない自然な並列ブレンドが行われる。

### 2.4 視覚化（ビジュアライザ）仕様
ウィンドウ面積の約65%をメインモニターに割り当て、「どこが・どれだけ削られたか」を色で直感的に判別できるように描画する。

1. **差分カラー可視化（Cutout / Gain Reduction Highlight）**:
   - **残った音（Post-Duck波形）**: ダッキング後に実際に鳴っている音声波形を明るいクールグレー（`#C8D6D5`）で描画する。
   - **削られた音（Gain Reduction差分エリア）**: 処理前（Pre-Duck）と処理後（Post-Duck）の波形の差分（＝削り取られた音量領域そのもの）を、半透明（アルファ値 `0.35`）のカラー塗りつぶしでハイライト描画する。
2. **減衰深度に応じた動的カラー変化（Depth-Mapped Color）**:
   - ゲインリダクション（GR）カーブのラインおよび差分ハイライトの色は、現在の減衰量（dB）に応じてリアルタイムに色相が線形補間される。
     - 浅い減衰（$0\text{ dB} \sim -6\text{ dB}$）: **シアン系**（`#45B8AC`）
     - 中程度の減衰（$-6\text{ dB} \sim -15\text{ dB}$）: **アンバー / イエロー系**（`#D99B26`）
     - 深い減衰（$-15\text{ dB} \sim -\infty\text{ dB}$）: **クリムゾンレッド系**（`#D9483B`）
3. **タイムベース基準と再生停止時の挙動**:
   - 表示時間幅を `1 Beat` / `2 Beats` / `1 Bar` / `500 ms` / `1000 ms` から選択可能とする。
   - **DAW再生中**: `1 Beat` / `2 Beats` / `1 Bar` 選択時はホストのBPMに同期した時間幅でスクロール描画する。
   - **DAW再生停止中**: ホストBPMが取得可能な場合はそのBPM換算の時間幅（例: $120\text{ BPM}$ なら $1\text{ Beat} = 500\text{ ms}$）を維持し、取得不可の場合は `500 ms` 固定幅にフォールバックする。また、音声入力・トリガーともに無音状態が `1.0秒` 継続した時点で波形スクロールを停止し、直前のフレームを静止（フリーズ）表示する。
4. **数値ゲインリダクション表示＆ルーティング診断**:
   - ビジュアライザ右下隅に現在の最大ゲインリダクション数値（例: `Max GR: -14.8 dB`）を等幅フォントで常時表示する。
   - 画面上部のトップバーに `ch 3/4` の信号監視ステータスを表示する（入力あり: `SC: ACTIVE (-12.4 dB)` / `Audio` モードで無音時: `SC: NO SIGNAL (Route to ch 3/4)`）。

## 3. パラメータ一覧

すべてのパラメータは `juce::AudioProcessorValueTreeState`（APVTS）で管理し、REAPERのオートメーション、パラメータモジュレーション、およびプロジェクト/プリセット保存（`.rpl` / FX Chain）と完全同期させる。

| パラメータID | 表示名 | 型・範囲 | デフォルト値 | 単位 | 備考・スキュー・制約設定 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `mode` | Mode | Choice: `Sync` / `Audio` / `MIDI` | `Sync` | - | トリガー方式の切り替え |
| `sync_rate` | Rate | Choice: `1/1`, `1/2`, `1/4`, `1/8`, `1/16`, `1/4T`, `1/8D` | `1/4` | Note | Tempo Sync時の周期 |
| `sc_detect` | Detect Type | Choice: `Follow` / `One-Shot` | `One-Shot` | - | Audioモード時の検出方式 |
| `threshold` | Threshold | Float: `-60.0 〜 0.0` | `-18.0` | dB | Audioモード時の検出閾値 |
| `depth` | Depth | Float: `0.0 〜 100.0` | `80.0` | % | 最大減衰量（100%で完全無音） |
| `attack` | Attack | Float: `0.0 〜 100.0` | `2.0` | ms | 対数スキュー（中央値 `10ms`）。Riser・パッド等のスロー吸い込み効果にも利用可能 |

| `split_enabled` | Split Active | Bool: `Off` / `On` | `Off` | - | 低域限定ダッキングの有効/無効 |

| `midi_vel_sens` | Vel Sens | Float: `0.0 〜 100.0` | `0.0` | % | MIDIベロシティによるDepth変調感度 |
| `sc_hpf` | SC HPF | Float: `20.0 〜 2000.0` | `20.0` | Hz | 検出信号用HPF（ガバキックの超低域カット等は `80Hz` 推奨） |
| `sc_lpf` | SC LPF | Float: `200.0 〜 20000.0` | `20000.0` | Hz | 検出信号用LPF。DSP側で `effective_lpf = max(sc_lpf, sc_hpf + 10.0 Hz)` にクランプし帯域逆転を防止 |
| `sc_listen` | SC Listen | Bool: `Off` / `On` | `Off` | - | `On`時は `ch 3/4` の検出信号を `ch 1/2` へソロ出力 |

## 4. DSPおよびオーディオ処理要件

### 4.1 ゼロレイテンシとポップノイズ防止仕様
- **遅延ゼロ（PDC = 0 samples）**: 先読みバッファを持たず、リアルタイム処理遅延を常に `0 samples` とする。
- **クリック/ポップノイズ防止の最終段スムージング**:
  - `Depth = 100%`（完全無音）かつ `Attack = 0.0 ms` の設定や、`Tempo Sync` の周期リセット・停止収束時においても波形の急峻な不連続（プチノイズ）を防ぐため、算出された最終ゲイン係数 $g_{\text{target}}$ に対して**時定数 $\tau = 1.0\text{ ms}$ のワンポールローパススムージングフィルタ**を常時適用する。
  - **実装検証メモ**: 44.1kHz / 48kHz 実機環境において、ゲイン `0.0` から `1.0` への立ち上がり時に聴感上のクリックノイズがわずかに残る場合は、時定数 $\tau$ を `1.5 ms 〜 2.0 ms` の範囲で耳テストにより微調整すること。

### 4.2 リアルタイムスレッドの安全性とSPSC FIFOパケット粒度
- `processBlock()` 内でのヒープメモリ確保（`new`, `malloc`, `std::vector` のリサイズ等）、ロック（`std::mutex`）、システムコールを完全に禁止する。
- **SPSC FIFO 転送レートとオーバーフロー対策**:
  - オーディオ処理スレッドは **`128 samples` 単位**（44.1kHz時 約 `2.90 ms` 間隔、60fpsの1フレーム `16.67 ms` あたり約5〜6パケット）で、区間内の Pre波形ピーク値、Post波形ピーク値、および最小ゲイン係数（最大GR値）を1パケットに集計し、固定長ロックフリーリングバッファ（容量 `2048` パケット＝44.1kHz時 約 `5.95秒` 分）へプッシュする。
  - **バッファ満杯時のドロップ挙動**: FXウィンドウが閉じられている（Editorが存在しない）間など、GUIスレッドがFIFOを読み出さずバッファが満杯になった場合は、`processBlock()` 側で最も古いパケットを1つ破棄（読み捨て）してから最新パケットを書き込むことで、ロックやエラーを起こさず常に直近の履歴を保持する。

### 4.3 REAPERバス構成
- `BusesProperties` にて、メイン入出力（Stereo: `ch 1/2`）とサイドチェイン入力（Stereo: `ch 3/4`、デフォルト有効）を明示的に定義し、REAPERの「プラグイン ピン・コネクタ」で自動的に `3/4 -> Side Chain 1/2` としてマッピングされるようにする。
